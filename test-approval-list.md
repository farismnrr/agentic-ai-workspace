## 1. Decision procedure

Apply per file and per function in order:
1. If it drives only a public boundary (HTTP, MCP, built binary, browser, Docker, or real DB through the app), keep it unless an exact replacement already exists.
2. Otherwise keep only behaviors in auth/authz; crypto/credentials; cross-user/project isolation; sandbox/egress/SSRF/privilege; DB integrity/migrations/transactions; critical concurrency/data loss.
3. If a bash scenario can trigger the same failure deterministically, delete the old test and name the replacement below. If not, retain it with a registry row and a concrete reason.
4. Delete mock-only, coverage-chasing and duplicate tests. Helpers stay only when a retained test uses them.
5. No security or integrity check disappears without an equal-or-stronger named replacement.

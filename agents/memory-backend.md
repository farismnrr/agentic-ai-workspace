# Backend memory

Durable lessons about the Go backend, kept for AI agents. Add one only when it is likely to matter again; fix stale facts instead of appending contradictions.

1. Migrations in `internal/platform/database/migrations/` are an append-only journal with checksums: never edit or delete an applied file; every schema or query change is a new numbered file. Startup fails if history was altered.
2. The server is its own OAuth 2.1 authorization server (`modules/oauth`) and hosts MCP spaces (`modules/space`; first is `modules/coding` at `/api/coding`). Tokens are opaque and stored hashed; a space accepts only tokens whose `resource` is its own URL. Features meet only in `internal/bootstrap/bridges.go`. Open endpoints (sign-in, sign-up, OAuth) stay rate limited via `bootstrap/limits.go`. Outgoing calls to person-chosen addresses (providers, CIMD) must use `platform/egress` (IP checked at dial time); hosted kinds have fixed addresses, gateways are loopback only.
3. Discovery contract: protected resource metadata at `/.well-known/oauth-protected-resource/api/<slug>`, server metadata at `/.well-known/oauth-authorization-server` and `openid-configuration`, CIMD (SSRF-guarded, public IPs only), DCR, PKCE S256, RFC 9207 `iss`. Keep `internal/bootstrap/e2e_test.go` passing when touching any of it.
4. A new space is a `space.Space` plus a bootstrap mount, never an `oauth` special case; the coding space is always on and strictly per person and per app: `bootstrap/connectedapps.go` maps the token's user id and client name to a project (`projectapp.ForApp`, `projects.source`, one live project per user and app) whose folder `agentTools.services` serves, the same path the agent uses (never share a folder, runner, or undo path across users or apps; the old `DATA_DIR/workspaces` is deleted at startup). Activity undo blobs are wrapped with the project id (`wrapUndo`). Tasks and `run_command` (bash, exec scope, asks every time) run only through `platform/sandbox`: one throwaway Docker container per run via the Engine API (`SANDBOX_IMAGE`, the shared toolbox image whose label `io.masihawam.toolchains` feeds the agent prompt; toolchains stay in the image, never per user; per-workspace `/cache` and `/run/egress` socket, removed by `Engine.Forget`; no network interface, `/tmp` must stay exec for Go/Java, read-only root, cap-drop ALL, no-new-privileges, memory/cpu/pids/fsize limits, workspace bind mount or data-volume `Subpath`, owner-labelled so startup cleanup only removes the server's own leftovers), under one shared `runner.Engine` that opens Docker lazily and never blocks startup. Tests that run tasks skip when no Docker daemon is reachable. `coding/domain.Tools()` is the single tool catalogue; calls pass permission, then scope, then run, are always logged, and no tool may reach `.workspace/` (task definitions). Write and run stay separate scopes, Off by default.
5. Adapters answer errors with `c.Status(n).JSON(httpserver.Failure(code))`; returning a wrapped error after writing a response makes Fiber overwrite it with a 500. There is no separate chat: every message is a `modules/task` thread, a run that changed nothing ends as an answer (`done`, no receipt), reads run unprompted and every write or run asks (`needsApproval`) unless the person set Skip approvals for the space. `coding/domain.Tools()` (including `start_site`/`stop_site`) is the one catalogue: the Spaces & tools switches gate the agent (`task` `ToolGate`: not offered, refused at call time) and MCP alike; an off tool is never bypassed. `start_site`/`stop_site` are not in `Tools()` (no toggle of their own); `codingdomain.SwitchOf` makes them follow `run_command`. Tests that run tasks must switch the changing tools on (`rigOn` does); they are off by default.
6. Sites (`modules/site`, `docs/sites.md`) serve untrusted code from the app's own origin, so isolation is browser-enforced and every layer stays on: `Content-Security-Policy: sandbox` without `allow-same-origin` on every `/run` answer (errors too; the app's own CSP is replaced), the Fetch Metadata guard in `RequireSession` (cross-site requests refused except navigations), the proxy dropping `Cookie`/`Authorization` going in and `Set-Cookie`/`Clear-Site-Data`/`Service-Worker-Allowed` coming out, hop-by-hop headers stripped before our own are added, and the destination always the site's own Unix socket. Never add `allow-same-origin`, never forward the session, never take host or port from the request. A sandboxed page's own requests carry no login, so private sites use `Site.Decide`: the signed-in owner always passes; anyone else passes only a non-page request with a valid ticket (HMAC of the token, the holder and an expiry, 4 hours, key made at startup, in the address as `/~<ticket>/`; the holder is the User-Agent, plus the client IP only when `CLIENT_IP_HEADER` is set, because behind a proxy without it every visitor shares one address); a page (GET navigation) always needs the owner and otherwise gets the 403 sign-in page. The uuid alone never opens anything, and `Sec-Fetch-*` headers are forgeable outside browsers, so never base private access on them alone; tests must cover forged headers. Visibility is changed only by the owner, never by an agent tool. Sites are one per project, manual stop only, capped per user and in total, and reset at startup.
7. Verify site changes in a real browser, not only with Go tests: `make e2e-sites` starts the full app (real SPA, real container, `TestServeSiteForABrowser`) and runs `scripts/e2e-sites.ts` with a fresh signed-out Playwright browser (installed globally; scripts load it from `npm root -g`). It found what in-memory tests missed (a forged `Sec-Fetch-Dest` plus the address was enough to read a private site). Residual risk to keep documented: a ticketed address copied exactly, from the same User-Agent and IP, still loads sub-resources until it expires.
8. The runtime image is distroless (no curl, no shell), so its `HEALTHCHECK` is the binary itself: `agentic-ai-workspace healthcheck` (`platform/healthcheck`, wired in `cmd/workspace`) requests `/api/health` on `127.0.0.1:$PORT`. Compose inherits it, which is what makes `docker ps` say `(healthy)`; do not add a second healthcheck in the compose files.
9. GitHub (`modules/github`, Settings, Integrations) is a GitHub App user-to-server flow (web flow + PKCE, `state` single use and bound to the signed-in person). Tokens live sealed in `github_connections` (`platform/secretbox`); `ghu_` lasts 8 h and every refresh invalidates the old refresh token, so `Service.lock` serialises per person and a rejected refresh deletes the connection (a 5xx must not). A command gets the token only through `runner.GitSource`, bound per project in `bootstrap/github.go` (`useGitHub`): the owner comes from `projects.Owner(projectID)` at run time, never from the caller. The token goes in `GIT_CONFIG_*` env + `GH_TOKEN` (no file, no URL), only when the workspace has its proxy socket, with github hosts on a socket of its own (`Hub.Dir(id, extra...)` keys sockets by host set so a site and a command never flip each other's). Sites (`SiteSpec`) never get a token or the github hosts. Keep `bootstrap/github_test.go` and `application/*_test.go` passing when touching it.
10. Context, not cost, bounds a task (`task/application/compact.go`). Never sum a task's usage against a cap: input tokens are re-counted every turn, so a long task trips it and Continue cannot recover (the old 400k `TokenCap` did exactly that). The size that matters is the last call's `Input+Output` against the model's window (`provider/domain/context.go`: chosen, else `[1m]` suffix, else 200K); past `window-33K` the model summarises (client-side, so every provider kind works) and `Block.Summary` marks the notes that replace everything before them in `sinceSummary`. Summarise only between tool rounds so tool_use/tool_result pairs stay whole, and treat a summary that calls a tool or is empty as a miss, never as a failure of the task.
11. Effort is `task/domain/effort.go` (`""`, low, medium, high, xhigh, max), stored per task and defaulted from `preferences.default_effort`; clients send it as `reasoning_effort` (OpenAI-style, incl. 9router) or `output_config.effort` (Anthropic) and omit it when empty, never a made-up default. Checked against a real 9router (`cx/gpt-6-luna`, Oct 2026): `reasoning_effort` reaches OpenAI, which accepts none, minimal, low, medium, high, xhigh, max and answers anything else with a 400 naming them (`param: reasoning.effort`), even though 9router's `/v1/models` says `thinkingEffortSupported: false`, so never trust that flag to hide the control. Which levels a model takes is the provider's call (the API returns `efforts` per model from `provider/domain/model.go` `EffortLevels`: a gateway that describes a model decides, a model reported as not reasoning gets none, `none` is dropped when it cannot switch thinking off, and a gateway that says nothing gets every level, so a provider added behind a gateway needs no code change; direct providers get their documented list; the UI never keeps its own list). A 9router gateway lists per-model `capabilities` at `/v1/models` without a key (`contextWindow`, `reasoning`, `thinkingEffortSupported`); its real window sizes differ from a 200K/1M guess (272K and 872K for `[1m]`), so `probe` reads them (`capabilities.contextWindow`, `context_length`, `context_window`, `max_input_tokens`) at Verify into `model_windows`; precedence is chosen (`model_settings`) > reported > `[1m]` > 200K, and Refresh in Settings re-reads them.
12. What 9router reports per model (`/v1/models`, no key needed) is read by `provider/adapter/probe` into `model_catalog` at Verify/Refresh (a new provider behind the gateway shows up only after Refresh): `capabilities.contextWindow`, `reasoning`, `thinkingCanDisable`, and `thinkingFormat` (openai, claude-adaptive, claude-budget, gemini-*, deepseek, kimi, zai...). 9router translates one OpenAI-style `reasoning_effort` for every backend and clamps what a model cannot take, so offer one level list, not one per format. Its Claude (`cc/`) models answer with an event stream even when `stream` was not asked, so `openai.Client.Complete` falls back to reading SSE (`transport.ErrEventStream`); without that, compaction summaries on a Claude model failed. Test against the real gateway with `cx/`/`cc/` models before trusting a format guess.

# Frontend memory

Durable lessons about the Svelte frontend and routing, kept for AI agents. Add one only when it is likely to matter again; fix stale facts instead of appending contradictions.

1. Headings get `font-display` from the base layer in `web/src/app.css`. Serif is for section headlines only; navbar and footer wordmarks use Inter 600; the logo is the inline stroke SVG in `LogoMark.svelte`.
2. Scroll reveals use the `reveal` action in `web/src/shared/motion/`; the hidden state exists only under `prefers-reduced-motion: no-preference` with the `js-reveal` root class. Below-the-fold sections use `LazySection` with the section `id` on the placeholder.
3. Favicon, touch icon, and manifest are static files in `web/public/`; Go serves hashed `/assets/*` as immutable and `index.html` as `no-cache`.
4. The SPA has no router library: `web/src/app/router.ts` is a History API router over a store of parsed routes. Add static paths to `staticRoutes` and `/app/*` patterns to `appPatterns`. The Go fallback must force status 200; missing `/assets/*` stay 404.
5. Every workspace screen talks to the real API (`logic/*-api.ts`, plain-TS stores in `logic/workspace-store.ts` kept fresh by `AppShell`, `logic/thread.ts` for one task); `/app/*` requires a session. `content/` holds copy only, never sample data. Never fake success; a page without a backend says so plainly. Notifications are per device (`logic/notify.ts`, localStorage + Notification API). The Inbox and counts are derived from tasks in `logic/derive.ts`.
6. The workspace uses the compact `app-ui` scale from `shell/AppShell.svelte` (14px text, hairline-divided flat rows, no card shadows, `btn-sm`, `h-10` inputs). Pages declare `spacious`, `dense`, or `split` width; split pages own their height and scroll inside panes. Home's greeting is the only serif.
7. Task status looks come only from `content/status.ts`; the thread is the typed `TaskEvent` union from the API rendered by `task/thread/EventItem.svelte`; consecutive actions collapse (`task/thread/blocks.ts`); the composer is one component (`components/ComposerBox.svelte`).
8. The agent loop (`modules/task`) rebuilds from the stored transcript, so a task can pause for an answer and resume. Proof is derived only from tasks the server ran (`application/proof.go`), never from the agent's claims. API keys are read only through `provider.Service.Credential`.
9. Settings use `settings/parts/` with tabs driven by `settings/settings-nav.ts`; create-style forms open in a daisyUI `modal`.
10. Icon names live in `shared/ui/icon-names.ts`; `Icon.svelte` holds only the paths.
11. Required bindable props are declared `value?: string | undefined` with `$bindable('')`. `.svelte.ts` rune modules are not parsed by ESLint; keep shared state in plain `.ts` stores.
12. Sites: the `sites` store is loaded by `refresh()` with projects and tasks (the `changed` stream event already triggers it), the sidebar shows only running apps (`SidebarSites.svelte`) with a Stop button, `/app/sites` owns visibility (going public always goes through `ConfirmModal`), and a `site` thread event renders `SiteCard.svelte`. App links always use `target="_blank" rel="noopener noreferrer"` and are never SPA routes: `/run/*` must stay unknown to `router.ts` so clicks do a real page load. Approval cards show plain questions; the technical line sits behind "Show details" and only high risk gets a badge.
13. Empty states all use `shared/ui/EmptyState.svelte` (icon, one-line title, why it is empty and what to do, optional single action), following common design-system guidance: first use, no results and cleared data get different wording, an action appears only when it resolves the emptiness, compact panels drop the big spacing, and `bordered` is for areas not already inside a card. Copy lives in `content/*` as `{ title, body }`. Sign-in `next` goes through `goTo` in `router.ts`, so paths the SPA does not own (such as `/run/*`) load as real pages.
14. Unknown SPA paths resolve to the `not-found` route (not the landing page). `/not-found` and `/forbidden` are real routes that Go answers with 404 and 403 (`pageStatus` in `platform/httpserver/spa.go`), and `/run` redirects page requests there (`site/adapter/http/errorpage.go`); non-page requests under `/run` keep plain-text errors. The shared `BrandLink` and `nextPath` (in `shared/`) serve both auth and errors.
15. Responsive rules that bit us: a Tailwind `grid` without `grid-cols-1` has an implicit `auto` column that grows to its widest child, so truncated rows and scrollable navs push the page sideways on phones; always write `grid grid-cols-1 md:grid-cols-[<fixed>_minmax(0,1fr)]`. Use `min-h-dvh`/`100dvh`, never `100vh` (mobile browser bars). The phone bottom bar is `shell/MobileBar.svelte` (daisyUI `dock`, `md:hidden`; `AppShell` pads the page and hides it on the task route). To check a change, run a throwaway instance (`PORT=8099 DATA_DIR=<temp> bin/agentic-ai-workspace`, never the user's 8081 container), sign in through the API and have Playwright load each route at 390, 820 and 1024 px, failing on `scrollWidth > innerWidth`.
16. A native `<details class="dropdown">` never closes by itself: `shell/UserMenu.svelte` adds outside-click and Escape handling and reads `details.open` directly (the bound state lags one tick behind the `toggle` event). New popups copy the palette/user-menu surface (see the design system) instead of daisyUI defaults with `shadow-lg`.
17. Inside the workspace (`app-ui`) text gets a fixed pixel line height (22px for 14px text), inherited by everything. A single-letter tile smaller than that (the 16px sidebar project tile) then has a grid row taller than itself, and `place-items-center` centres the letter in the row, not the tile, so it sits low. `ProjectTile` is `leading-none` for that reason; give any new tile or badge that holds one glyph `leading-none` too. To check centring, screenshot the element at a high `deviceScaleFactor` and measure the letter's ink gaps against the tile (sub-pixel offsets of ~0.5px are Chrome rounding the baseline; try a font size that leaves an even gap, which is why the 16px tile uses 10px, not 9px).
18. A keyed `{#each ... (item.text)}` over data the server or an agent produces must never key on content that can repeat. Svelte 5 throws `each_key_duplicate` and the whole block stops updating, with no visible error: the Proof tab showed Plan or Changes instead because a task ran the same `gh` command twice (two checks with the same text). Key lists of generated text by position (`as item, index (index)`) or by an id the server made; keep content keys only for fixed sets. To catch it, load a task whose data repeats and watch the page's console for `svelte.dev/e/each_key_duplicate`.
- **Project Env and databases.** The project detail page owns Env and passes
  its ID to `projects/env/VariablesSection.svelte` and `DatabaseSection.svelte`.
  Settings has no Env tab or project picker. `DatabaseSection` offers SQLite
  plus configured PostgreSQL, MySQL and MongoDB choices; unconfigured kinds are
  disabled, and old custom connections stay read-only. Switching detaches only
  local metadata and managed Env values, never remote databases or data.
  Projects receive `DATABASE_SSL_CA` when configured, never the client cert or
  key. Responses never reveal saved secrets. `env-logic.test.ts` uses Vitest;
  `make frontend-verify` runs `npm test` locally and in Fast CI.
- **Admin Settings.** Session `/api/auth/me` includes `role`. Hide the shared
  Database tab for users and redirect direct SPA visits; backend authorization
  remains authoritative. Other Settings tabs edit the signed-in person's data.
- **Question form.** A question event is a form (`questionsOf` turns old single questions into one). Answers go up as `string[][]`; a typed reply replaces the pick of a single question and is added to a multi one. Child fields get their state through a `draft` prop and an `onchange` callback, not `bind:` on an array item (the strict lint forbids the `!` that needs).
- **Agent text is markdown.** What an agent writes (chat bubbles, the PRD) goes through `DocText`: `logic/markdown.ts` reads headings, lists (with indent), tables, code fences, rules and quotes into blocks, `logic/markdown-inline.ts` reads `code`, **bold**, *italic* and links, and `InlineText` shows the spans as elements. Never `{@html}` for model output; only http(s) links become links. A plain `<p>{text}</p>` collapses newlines and shows the asterisks, which is what the chat did before. The ESLint rule `no-confusing-void-expression` rejects `{@render}` inside a snippet call chain, so use a small component (`InlineText`) instead of a snippet.
- **Black-box before saying done.** `make e2e-thread` (script `scripts/e2e-thread.sh`, server side `TestServeThreadForABrowser`) runs the whole app with a scripted model that starts a page, takes two real screenshots and runs a check, then drives the thread in Playwright and saves screenshots. Look at them. It found what unit tests and my own first fix missed: the agent's final text lives in the result card (`ResultCard`), not in a chat bubble, so any place that shows agent text must use `DocText`. It needs Docker, the sandbox image and `npm i -g playwright`; CI does not run it.
- **Guest-only pages.** `/login` and `/register` are `guestOnly` in `app/guard.ts`: `App.svelte` shows the spinner until `loadSession` knows, then sends a signed-in person on with `goTo(nextPath(search), true)` (replace, so Back does not return to the page; `nextPath` accepts same-site paths only, so no open redirect). The sign-in and register pages do not navigate themselves: they call `setUser` and the same guard redirects, which also covers the person who signs in elsewhere and returns. `scripts/e2e-thread.ts` checks it, and `scripts/e2e-sites.ts` checks the `?next=` to a `/run/` address; keep both scripts in step with copy changes (the sites one had gone stale after the 403 page was redone).
- **Style previews.** The pictures of the style families in a question form are drawn by `scripts/style-previews.ts` (Playwright on the host) from `scripts/style-preview.html` and each family's own `tokens.css`, and committed under `workspace/assets/style-previews/`; `assets/style-previews.ts` finds them by name through `import.meta.glob`. Run it again when a `tokens.css` or the template changes (`PW=$(npm root -g)/playwright node scripts/style-previews.ts`). Only families that look clearly different are drawn: the library has twins (clean/minimal, elegant/editorial/warm-editorial, neumorphism/claymorphism) and `modern` uses the indigo that marks a page as machine-made. A card shows `(Recommended)` as a badge (`readLabel`), but the answer keeps the whole label.
- **A live thread only appends.** `createThread` adds events past the last `seq`, so an answer to a question or approval already on the screen never arrived: the card kept its buttons while the task went on (only a reload showed it). `reconcile` reads the thread again once the task has left `needs-input` while something still shows as waiting. `make e2e-thread` answers the look question in the browser and caught it.
- **File browser.** `files/FileBrowser.svelte` (tree `TreeLevel`, `FileView`) is used on the project page and in the task panel's Files tab. CodeMirror 6 is loaded only when a file opens (`logic/editor.ts`, dynamic imports; one chunk per language), its colours come from daisyUI variables (`editor-theme.ts`), never a palette of its own. State lives in `logic/file-store.ts` (tree; only the newest read of a folder counts, reads finish out of order when files change in a burst) and `logic/file-view.ts` (the open file: disk, draft, `diverged`). The panel is narrow, so tree and file take turns (container queries `@2xl:`); grid columns need `minmax(0,1fr)` or the editor pushes the panel wider. Ctrl/Cmd+S is on the window, because pressing a button that then disappears (Keep mine) drops the focus out of the section. A `$state` rune conflicts with a local variable named `state` (store `$state`): name stores `shown`.
- **Diff view.** `changes/ChangedFile.svelte` + `DiffView.svelte` + `logic/diff-editor.ts` (merge code loaded when a diff opens). `@codemirror/merge` ships hard-coded red and green, so `diffTheme` in `editor-theme.ts` replaces them with the status roles and adds an edge bar so the lines are marked without colour. `ChangesTab` reads again on every new step and on the files stream (`logic/changes-store.ts`, newest read wins), starts Split when its box is 720px wide or more and lets the person pick.
- **Sidebar task pins.** `SidebarTaskRow.svelte` keeps the native pin button beside, not inside, the task link; use a stable “Pin task” label and `aria-pressed`. Only the sidebar exposes pinning, and the store patches the server response so cross-project pins appear immediately.
- **Composer attachments.** `DataTransfer.files` is readable in drop/paste handlers, not while dragging over; only use drag-over to show the highlight. Gate shared `ComposerBox` Send on every chip being ready and announce status changes politely. Preview ready images only, and revoke every object URL when its chip is removed or the composer is destroyed.
- **UI cleanup is reuse-only.** Search for existing feature and shared
  components, then use daisyUI patterns before writing markup. Avoid scoped CSS
  and arbitrary size utilities; keep the established controls, sizes and theme.
- **Visual checks need screenshots.** Compare affected workspace pages before
  and after with `scripts/shots.sh`; inspect every desktop and mobile capture.
  Source review alone misses overflow, excess surfaces and spacing drift.

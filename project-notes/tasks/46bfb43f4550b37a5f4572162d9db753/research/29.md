## Source-rooted findings
- Existing design-system says compact workspace, flat row + hairline, **no card shadow** and no nested card. This must be revised only after owner approves; brand colors/theme and 14px density remain.
- Project Checks: two loose intro lines, unbounded EmptyState, detached Add footer under a divider. Screenshot confirms disjoint hierarchy; propose one bounded section.
- Tasks/Archive: empty list content rests on flat canvas; collection container needed, flat internal rows preserved.
- SettingsSection: borderless header + divide-y; reused in Models, Persona, Team, Activity, Usage, Notifications, Connected, Account, Project Env/About. Propose controlled opt-in section surface, not blanket wrapping. Settings Spaces already has bordered tool panel; Integrations has bordered list, avoid double borders.
- Project New Project: choice gallery cards already appropriate; only details form may benefit from grouping. RepoPicker popover is a separate surface.
- Project Files/Task Files: editor/tree and diff are full-height split workspaces; adding cards around each pane/editor line would compromise density. At most a host boundary; keep existing Git markers and state warnings.
- Task: WorkPanel aside already base-100 and bordered; Plan empty notice is isolated small dashed patch. Transcript needs author/source/event rhythm, not card on every chat. Approval/Question/Result/PlanReview cards are semantically important. External vs internal reports cannot be visually conflated.
- Internet Access: form already framed, pending/history are standalone sections; normalize with a single section hierarchy and risk/approval meaning.
- Sites/Extensions: populated list has card; empty-state treatment differs. Inbox already uses split view, preserve; optimize empty state only.
- Auth/Consent/Error: separate branded design; no new workspace card required.
- Shell/command palette/user menu: remain navigation/popover surfaces, not content cards.
- Prevent a universal 'wrap everything in card' migration: no card-per-row, card-per-message, modal-within-card, nested approval/receipt, visual AI-slop.

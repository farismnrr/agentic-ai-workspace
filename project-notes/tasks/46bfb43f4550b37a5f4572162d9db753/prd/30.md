# PRD v2 — Comprehensive UI Surface & Card Hierarchy Audit
**Status:** DRAFT — owner approval required. **Repo:** agentic-ai-workspace/dev @ e461846. **Scope:** UI visual only. **Companion audit:** project-notes/tasks/e0a82830063b6f5992a04f884e412147/ui-coverage-matrix.md — 154/154 Svelte files indexed.

## 1. Purpose and evidence
Current design favors compact 14px workspace text, flat rows and hairlines. Yet page descriptions, empties and CTAs float apart on the canvas (Project Checks and Task Plan screenshots), while some list surfaces are already correctly outlined. **Goal:** one quiet section surface per coherent function, flat rows inside; never indiscriminately wrap every element in a card.
- Read-only source audit: 154/154 Svelte files (135 workspace + 19 app/auth/error/shared). All route types, 11 Settings tabs, 5 standard Project tabs + conditional Internet access, 5 Task panel tabs + Chat, New Project wizard, modals and shared primitives categorized.
- Visual baseline: 60 screenshots = 30 route/tab combinations at 1280 desktop / 390 mobile via temporary local app. Representative contact sheets inspected, and two provided screenshots considered.
- **Important limit:** screenshot fixture task creation returned HTTP 409 no_model. Filled/streaming conversation, active approvals and many error/permission states were NOT captured; full browser coverage is an acceptance requirement, not a completed claim.

## 2. One coherent surface system
- **S Section:** base-100, existing semantic hairline --brand-border and rounded-lg/xl; header/description + body + empty/loading/error + optional footer/CTA in ONE outlined module. No new colors, shadows, gradients or glows.
- **R Row/list:** homogeneous tasks/projects/checks/site rows remain flat/divide-y within an S parent; no card per list item.
- **E Event/approval:** preserve existing cards for approval, questions, plan review, result proof, handoff, site/extension events. Status risk, role and “reported vs verified” must remain distinct.
- **W Workspace:** chat transcript, code editor, file tree/diff, full-height task panel, inbox split, sidebar, topbar, dock stay flush with independent scrolling. Never put an outer card around an entire conversation or editor.
- **C Choice:** existing template and image-option cards remain; do not wrap selection card grids again.
- **M Modal:** modal-box/popover already is a surface; avoid nested cards. Preserve dialog focus/Escape, errors and confirmation.
- **N No migration:** auth, register, OAuth consent, 403/404, icons/status labels retain their own styles.
- **EmptyState:** reuse compact inside S (no second dashed border), icon + one-line title + explanation + at most one useful CTA. Populated, loading, error and empty states keep the SAME parent boundary.
- Keep original daisyUI/Tailwind theme, typography, accessibility, semantic brand/status roles and responsive density. No new UI library or backend modification. Update docs/design-system.md and agents/memory-frontend.md only AFTER approval.

## 4. Acceptance criteria (not marked passed)
1. Every route, all 11 Settings tabs, all Project/Task tabs including conditional Internet access checked for empty/filled/loading/error and relevant selected/disabled/permission/readonly/streaming states.
2. Capture and inspect before/after at **390, 820, 1024 and 1440px**, not just existing 390/1280 baseline; no horizontal overflow, detached CTA, excessive whitespace, double border or clipped modal/editor/composer.
3. Create isolated fixture with a working model and realistic filled tasks, active approval/question, external roles, progress/compaction, Git diffs, long files, admin/non-admin and failed API states. Screenshot evidence is mandatory before declaring those cases verified.
4. Check CTA actions, CRUD, filtering/bulk, New Project, Settings forms, site/extension actions, modal Escape/focus, task stream/follow-up, document tab, file save/diff. No changed API, auth, task lifecycle or proof logic.
5. Semantic statuses use text/icons; WCAG AA contrast, keyboard focus and reduced motion intact; popup and sticky layout behavior preserved.
6. Review rejects card-per-row/chat, nested card stacks, fake data, unrelated UI changes, shadows/glows/gradients or new tokens.
7. Use before/after screenshot comparison, targeted browser black-box, Svelte check/lint/build. Full CI and new whitebox tests not default.

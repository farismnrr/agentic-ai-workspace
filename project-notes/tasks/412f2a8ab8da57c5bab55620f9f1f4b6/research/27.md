## Technical references

- MCP’s lifecycle negotiates protocol versions and capabilities. Tool support does not guarantee support for task extensions or elicitation; clients advertise capabilities. HTTP authorization is carried on every request, and access tokens must not be put in URL query strings. [Lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)
- Streamable HTTP supports request/response and may use SSE; disconnection alone does not mean cancellation. The MCP Tasks extension is separate from core tools and describes polling, `input_required`, and task-associated elicitation. [Transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [Tasks extension](https://tasks.extensions.modelcontextprotocol.io/specification/draft/tasks)
- Repository `go.mod` pins MCP Go SDK `v1.8.0`. The official release is dated 14 September 2026 and supports protocol `2026-07-28` and earlier listed versions. The Go SDK roadmap still lists MCP Tasks as experimental; **unverified:** this checkout’s SDK integration does not expose MCP Tasks or elicitation handlers. [`go.mod:12`](</workspace/go.mod:12>), [Go SDK release and compatibility](https://github.com/modelcontextprotocol/go-sdk/releases), [Go SDK roadmap](https://github.com/modelcontextprotocol/go-sdk/blob/main/ROADMAP.md)
- OpenAI documents MCP Events for ChatGPT Work chats, with webhook delivery; it says polling and streaming modes are unsupported by that integration. Events require MCP 2.0 and persistent subscription storage. The project’s current MCP setup does not implement `events/list` or webhook subscriptions. [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events)
- ChatGPT custom MCP support is conditional on account/workspace access: current OpenAI guidance says full read/write MCP is in beta for Business, Enterprise and Edu; Pro connections are read/fetch only. ChatGPT connects to remote servers, not directly to a local server. [Connecting custom MCP servers](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)
- Gemini API function calling lets an application execute declared functions and return their results. Separately, Google documents remote Streamable HTTP MCP servers for Antigravity. Neither establishes that every Gemini surface supports this server’s auth flow, elicitation, notifications, or plan lifecycle. [Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling), [Antigravity MCP servers](https://ai.google.dev/gemini-api/docs/antigravity-agent)
- For dispatch idempotency, the current work store already uses an idempotency key plus request hash, and plan updates use revisions. A transactional outbox is the standard pattern when a database write and event/dispatch must not diverge; consumers must tolerate duplicates. [IETF Idempotency-Key draft](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/), [AWS transactional outbox guidance](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)

## Risks/unknowns

- The most direct requirement gap is the missing validated initial role: `begin_work` can create a work session with an empty active role.
- Work tools that persist state share `coding:read` and the `log_message` switch. That permission does not currently approve implementation, but it is broad for state-changing tools.
- An open external work session can remain task status `working`; the thread displays “Working on it” without checking the persisted work summary’s stale flag.
- No durable external-plan approval identity, immutable approved revision, approval audit record, or approval-to-dispatch outbox was found. The plan revision and operation idempotency are useful existing primitives, not an approval contract.
- Official Go SDK advisories list earlier affected ranges (`<=1.4.0` or `<1.3.1`) for published issues; the pinned `v1.8.0` is outside those ranges. The HTTP handler also explicitly disables localhost protection while relying on OAuth bearer auth, so preserve and review that deployment assumption. [Go SDK advisories](https://github.com/modelcontextprotocol/go-sdk/security/advisories), [cross-site tool execution advisory](https://github.com/modelcontextprotocol/go-sdk/security/advisories/GHSA-89xv-2j6f-qhc8), [`coding.go:41`](</workspace/internal/bootstrap/coding.go:41>)
- I did not establish whether current ChatGPT or Gemini clients support elicitation for this exact integration or whether Gemini’s documented MCP support covers all required OAuth behavior.

- Exercise each actual task status and verify visible icon/label, screen-reader name, contrast, focus, and reduced-motion behavior. Treat “stopped” as task `failed` plus work `stopped`; do not add a task status unsupported by the domain.
- Check the sidebar status for queued, working, needs-input, review, done and failed. Verify that no color-only marker carries the sole status meaning.
- For lifecycle persistence, test missing/invalid/disabled roles, role changes, role event attribution, concurrent work sessions, plan revision conflict/retry, blocked/resume/completion, and legacy `log_message` history.
- For streaming, test event creation, same-event updates, missed hub wake-ups, heartbeat recovery, reconnect, refresh, late responses and stale external sessions. Confirm terminal/blocked state removes active loading indicators.
- For approval/handoff, tests need to cover authorization, project/work ownership, exact plan revision, concurrent and repeated approval, timeout retry, dispatch failure/restart, and ensuring the external client cannot start internal execution with read-scoped tools.
- Check Settings → Archive/Extensions and direct deep links at desktop, tablet and mobile sizes; verify active navigation, refresh, back/forward and project-scoped Extensions.

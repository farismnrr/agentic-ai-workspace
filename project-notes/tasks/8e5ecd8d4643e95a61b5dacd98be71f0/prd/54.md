## Overview
Most tests call package internals with fakes. They are slow to maintain and break without catching real bugs. We keep tests that use the real system through HTTP, MCP, the real database, a browser or Docker. These are now written in bash. White-box Go tests stay only for super-critical logic, each with a written reason black-box testing cannot do the job.

## Goals and non-goals
- **Goals:**
  - Delete about 70% of the Go test files.
  - Make black-box the default, enforced by a registry and a guardrail.
  - Put every test, script and fixture under `test/` with one naming scheme.
  - Keep Fast quick, and record before and after times.
- **Non-goals:** Coverage targets. New frameworks. A second server or port. Go code for black-box tests.

## Decision on the Go constraint (recommended; flagged in Open questions)
Go white-box tests must sit in the same folder as the code they test, because they read unexported names. They cannot move to `test/` as they are.

| Option | Plain-words tradeoff |
|---|---|
| **A. Keep ~44 retained white-box files beside their code; `test/whitebox/` holds the registry and guardrail (Recommended)** | Works with Go as designed, and lint and `go test ./...` keep working. `test/` is the single index of everything, though not every file lives there. A guardrail fails any `_test.go` not listed. |
| B. Rewrite them as external Go tests under `test/` | Needs exported hooks added to production code, and a big rewrite. The SSRF, rebinding and rollback tests cannot be reached from outside. Rejected. |
| C. Replace them with bash scenarios | Cannot force DNS rebinding, a rollback mid-transaction or a revoke race. Weakens security checks. Rejected. |

**The 62 `internal/bootstrap` Go tests:** recommend keeping them as retained integration tests, listed in the registry as one group. They already run the real app over HTTP and MCP in-process, and rewriting them in bash is a large job with no new safety. After the bash scenarios exist, slice 2 marks any bootstrap test that exactly duplicates one for deletion. Two exceptions:
- `TestServeThreadForABrowser` and `TestServeSiteForABrowser` are used only to host the browser flows. They are replaced by the built binary in the bash e2e runner and then removed, or kept if the person's list says so.
- The bash harness must not need any Go code.

## Layout and naming (one convention)
Rules: lowercase kebab-case, a two-digit prefix for run order, and the suffix tells the kind.
- `*.test.sh` is a runnable bash scenario.
- `*.spec.ts` is a Playwright browser flow.
- `lib/*.sh` is sourced and never run directly.

```text
test/
  README.md                  how to run each suite (people-facing, short lines)
  whitebox/
    registry.md              table of retained Go white-box tests + reason
    check-registry.sh        guardrail: every unlisted *_test.go fails
  blackbox/
    01-auth-session.test.sh
    02-cross-user-isolation.test.sh
    03-mcp-token-scope.test.sh
    04-secrets-never-returned.test.sh
    05-restart-keeps-data.test.sh
    06-single-instance-clean-shutdown.test.sh
  e2e/
    run.sh                   shared runner: start app, run one flow, clean up
    01-projects.spec.ts
    02-sites.spec.ts
    03-thread.spec.ts
  smoke/
    binary.test.sh           was scripts/smoke-test.sh
    image.test.sh            was scripts/smoke-test-image.sh
    sandbox.test.sh          was scripts/smoke-test-sandbox.sh
  lib/
    app.sh                   start/stop/restart the binary, temp dir, free port, wait
    http.sh                  curl wrappers: api_get, api_post, assert_status, assert_json
    mcp.sh                   MCP calls (initialize, tools/call) with token headers
    assert.sh                small assertions and a pass/fail summary
  fixtures/                  static inputs (sample files, JSON bodies)
  run.sh                     entry: run a suite (blackbox, smoke, e2e, whitebox-check)
```

Moves (done with `git mv`, so history stays):
- `scripts/smoke-test*.sh` goes to `test/smoke/`.
- `scripts/e2e-*.sh` is merged into `test/e2e/run.sh`.
- `scripts/e2e-*.ts` goes to `test/e2e/NN-*.spec.ts`.
- `scripts/test-ship.sh` is checked in slice 2. It moves to `test/` only if it is a test.
- `scripts/check-guardrails.sh` stays where it is and calls `test/whitebox/check-registry.sh`.

Go white-box files keep Go's `name_test.go` form beside their code. `*_test.go` is a Go requirement, not a choice.

Frontend: `.ts` files under `test/` follow the "TypeScript only" rule. Playwright is pinned exactly in `web/package.json`, so no `.js` appears. It is allowed only for browser flows, driven by `test/e2e/run.sh`.

## Classification rules (decision procedure)
Apply in order to every test file and every named test:
1. **Does it drive only a public boundary?** That means HTTP, MCP, the built binary, a browser, Docker, or the real DB through the app. If yes, it is black-box and stays, unless rule 5 applies.
2. **Is the behavior in one of the six categories?** They are auth/authz; crypto/credentials; cross-user and cross-project isolation; sandbox/egress/SSRF/privilege; DB integrity, migrations and transactions; critical concurrency or data loss. If not, delete it.
3. **Can the bash harness trigger the failure deterministically?** If yes, delete the test and cover the behavior with a bash scenario (add one if none exists). If not, retain it as white-box with a registry row.
4. **Delete coverage-chasing and mock-only tests.** This covers getters, constructors, trivial mappers, and tests that mostly assert on fakes.
5. **Delete duplicates.** A white-box test is a duplicate when a bootstrap or bash scenario already checks the same outcome.
6. **No security or data-integrity check disappears without a named replacement.** The replacement must be equal or stronger and listed next to the deletion.

## Bash harness design (shellcheck-clean, files under 200 lines)
- **`lib/app.sh`:**
  - `app_start` makes a temp `DATA_DIR` with `mktemp -d`.
  - It picks a free port, then starts `$APP_BIN` with `PORT` and `DATA_DIR` set, as `smoke/binary.test.sh` already does.
  - It polls `/api/health` with a deadline, and fails with the app's log on timeout.
  - `app_restart` stops the app and starts it again on the same data folder.
  - A `trap` on EXIT stops the process and removes the folder.
  - The free-port step (ask the OS for a port, then close it) has a small race before the app binds. The helper retries with a new port if the app fails to bind, and the log says so.
- **`lib/http.sh`:** `curl -fsS`-style wrappers with a cookie jar per user, so cross-user checks use two jars. It asserts the status code and JSON fields with `jq`. Slice 3 confirms `jq` and `curl` are on the CI runner and in the dev sandbox, and states it if `jq` is missing.
- **`lib/mcp.sh`:** sends JSON-RPC to the MCP route with the bearer token and required headers, and asserts the tool results.
- **`lib/assert.sh`:** the pass/fail counter. Every scenario ends with a summary and a non-zero exit on any failure. Scripts use `set -eu` and `shellcheck` with no disables.
- **Scenarios:** the six files in the layout above. Each can run alone, because it starts its own app. `test/run.sh blackbox` runs them in order.
- **Browser flows:** `test/e2e/run.sh <name>` uses the same `lib/app.sh`, runs the pinned Playwright flow against the built binary (not a Go test host), and cleans up. The two `Serve…ForABrowser` Go tests become unnecessary if a flow can seed its data through the API. If one cannot, slice 6 notes which Go fixture stays.
- **Docker-boundary tests:** these keep self-skipping unless `SANDBOX_TEST_IMAGE` and Docker are present. They run in Full only.

## Makefile and CI design
- **Targets:**
  - `make blackbox` runs `test/run.sh blackbox`.
  - `make smoke`, `make e2e` and `make whitebox-check` run the other suites.
  - Old `e2e-sites`, `e2e-thread` and `e2e-projects` targets are replaced by `make e2e`.
- **`make verify`** (the local gate and Fast): guardrails (including the registry check), `shellcheck` over `test/`, frontend check, lint and build (no Vitest), `go mod tidy -diff`, `go test ./cmd/... ./internal/...`, Go lint, and `make blackbox`.
- **Fast** (`fast.yml`): jobs stay parallel. `blackbox` runs after `build`, next to the binary smoke test (now `test/smoke/binary.test.sh`). No Playwright, no Docker-boundary tests, no `-race`. The `changes` filter, if it lists `scripts/`, also lists `test/`.
- **`make verify-full`:** `verify`, `e2e`, Docker-boundary tests, and `-race` on the retained concurrency packages.
- **Full** (`full.yml`): the verify job runs `make verify-full`, with a Chromium install and the sandbox image test, before the merge to `main`. No new workflow files are added.
- **Timing:** DevOps records the last three green Fast runs per job with `gh run view` before any change, and the same on the final commit. A slower Fast run is explained in the report.

## Risks
- **No Docker in the team sandbox:** Docker-boundary tests and Playwright are verified only in CI.
- **Full can't be tested before release:** it runs only from `dev` and merges to `main`. The new e2e and Docker jobs are first proven on the next release. A failure blocks the merge, so it cannot break `main`.
- **Git write access:** the Researcher's `git fetch` failed on a read-only `.git/FETCH_HEAD`. DevOps confirms fetch and push work before slice 5.
- **Bash harness limits:** bash is weaker at structured assertions. Mitigated with `jq`, small helpers and `shellcheck`. Race and rebinding checks stay in Go.
- **Lost coverage:** guarded by rule 6 and the slice 2 list.
- **Leftover code:** deleted tests may leave unused helpers that lint flags. Each deletion slice cleans them up.
- **Moves breaking paths:** the Makefile, workflows, Dockerfile, docs and `scripts/install.sh` may name `scripts/smoke-test*.sh`. Slice 6 searches for every reference before the move.

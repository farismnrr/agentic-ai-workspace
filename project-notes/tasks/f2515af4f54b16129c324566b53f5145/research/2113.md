## Technical references (Developer)

**MySQL.** The project pins `go-sql-driver/mysql v1.10.1` in [`go.mod`](/workspace/go.mod:5). In that version, `mysql.Config` supports both `TLSConfig string` and `TLS *tls.Config`; `TLS` takes precedence. For per-call TLS, set `Config.TLS` directly to avoid global registration names and collisions. Otherwise, use `mysql.RegisterTLSConfig` with a unique name per call and set `TLSConfig` to that name. Build the DSN with `Config.FormatDSN`; set `ParseTime = true` if the project apps expect `time.Time` values from `DATETIME`/`TIMESTAMP`. The driver documents custom TLS configuration, DSN formatting, and `tls=preferred` plaintext fallback behavior in its [v1.10.1 README](https://github.com/go-sql-driver/mysql/blob/v1.10.1/README.md) and [`Config` source](https://github.com/go-sql-driver/mysql/blob/v1.10.1/dsn.go). The current probe uses `TLSConfig = "true"` and `FormatDSN` in [`mysql.go`](/workspace/internal/modules/dbconn/adapter/probe/mysql.go:16).

For provisioning, interpolate only strictly validated identifiers, quoted with MySQL backticks and embedded backticks doubled. Placeholders cannot stand for identifiers; MySQL’s prepared-statement guidance says markers are for data values, generally DML, not DDL. Therefore, do not rely on `?` for database or account names in `CREATE DATABASE`, `CREATE USER`, or `GRANT`. `IDENTIFIED BY ?` is not a safe assumption for this DDL path either: the documented `CREATE USER` grammar specifies a quoted authentication string. Prefer a safely escaped string literal for the generated password, or another explicitly supported password statement path. [`CREATE DATABASE`](https://dev.mysql.com/doc/refman/8.4/en/create-database.html), [`CREATE USER`](https://dev.mysql.com/doc/refman/8.4/en/create-user.html), [prepared-statement marker limits](https://dev.mysql.com/doc/c-api/8.4/en/mysql-stmt-prepare.html).

A project account can follow `CREATE DATABASE \`db\`; CREATE USER 'u'@'%' IDENTIFIED BY '...'; GRANT ALL ON \`db\`.* TO 'u'@'%';`. `'%'` allows connections from any host; the database-scoped grant keeps privileges on that database. MySQL warns that `CREATE USER` can expose cleartext passwords in server logs or client history files, so avoid logging statements or DSNs containing credentials. MySQL 8 uses `caching_sha2_password` by default; without TLS, initial/full authentication needs RSA password exchange, so the server must have its RSA key pair and the client must retrieve or know its public key. The driver exposes its server-public-key support in its [`Config` source](https://github.com/go-sql-driver/mysql/blob/v1.10.1/dsn.go). [MySQL authentication guidance](https://dev.mysql.com/doc/refman/8.4/en/caching-sha2-pluggable-authentication.html).

**MongoDB.** The repo pins `go.mongodb.org/mongo-driver/v2 v2.9.2` in [`go.mod`](/workspace/go.mod:18). The v2 import roots include `/v2/mongo` and `/v2/mongo/options`; the existing probe uses those imports and `options.Client().ApplyURI(...)` in [`mongodb.go`](/workspace/internal/modules/dbconn/adapter/probe/mongodb.go:11). The v2 options API has `SetAuth(options.Credential)` and `SetTLSConfig(*tls.Config)` ([pinned v2 options source](https://github.com/mongodb/mongo-go-driver/blob/v2.9.2/mongo/options/clientoptions.go), [migration guide](https://github.com/mongodb/mongo-go-driver/blob/v2.9.2/docs/migration-2.0.md)). Build admin clients with `options.Client().ApplyURI(uri)`; apply `SetAuth` if credentials are not already in the URI, and `SetTLSConfig` for in-memory TLS.

Create users through `client.Database("admin").RunCommand(ctx, bson.D{...})` if admin credentials authenticate against `admin`; run `createUser` on the target database to make `authSource` unambiguous. Set `roles` to `[{role: "readWrite", db: name}]`. On a duplicate user, check whether the existing credentials/roles are already correct; if they must be reconciled, `updateUser` replaces specified fields, including the full roles array. MongoDB notes that `updateUser` is unsupported on some Atlas tiers and requires role-management privileges. [`createUser`](https://www.mongodb.com/docs/v8.0/reference/command/createuser/), [`updateUser`](https://www.mongodb.com/docs/v8.0/reference/command/updateuser/).

**Project names and connection URLs.** Existing PostgreSQL project names are deterministic: `p_` plus the first 12 bytes of SHA-256(project ID), yielding a fixed lowercase identifier in [`provision.go`](/workspace/internal/modules/dbconn/adapter/provision/provision.go:152). Reuse that generated name for MySQL and MongoDB rather than project display names. The domain validates connection kinds, host, database/user lengths and environment names in [`connection.go`](/workspace/internal/modules/dbconn/domain/connection.go:71). It builds `postgres://`, `mysql://`, and `mongodb://` URLs and maps Mongo to `MONGODB_URL`; SQL kinds map to `DATABASE_URL` ([`connection.go`](/workspace/internal/modules/dbconn/domain/connection.go:99)).

The current MySQL/Mongo URL builder URL-escapes user, password and database path, and sets `tls=true|false` ([`connection.go`](/workspace/internal/modules/dbconn/domain/connection.go:106)). The desired Mongo project URL should include `authSource=<project database>`; when TLS is on, `tls=true`. The PRD’s MySQL “URL” example is an application URL (`mysql://user:pass@host:3306/db?...`), whereas the Go driver expects its driver DSN (`user:pass@tcp(host:3306)/db?...`) from `FormatDSN`. Use the latter inside Go MySQL apps.

**TLS mapping and project CA.** Map No TLS to no TLS config. CA only uses `RootCAs` and verifies both the server chain and host. Full also sets `Certificates` from the client certificate/key. With a literal IP host, Go checks the certificate IP SAN; a DNS-only SAN will not match. Keep `ServerName` unset only if the client library correctly derives it from the connection address. This mapping matches the standard Go [`tls.Config`](https://pkg.go.dev/crypto/tls#Config) behavior and Mongo driver’s TLS option ([TLS connection guidance](https://www.mongodb.com/docs/drivers/go/current/security/tls/)). The project should receive `DATABASE_SSL_CA` only, as the PRD specifies. Existing environment handling seals `SetSecret` values and reveals them for trusted use in [`service.go`](/workspace/internal/modules/env/application/service.go:112); shared provisioning already snapshots/restores managed environment values in [`service_shared.go`](/workspace/internal/modules/dbconn/application/service_shared.go:52).

**Settings migration and routes.** Current schema is at migration **049**, not 048: migration 046 creates singleton `shared_database_settings`; 049 adds the sealed certificate columns ([046](/workspace/internal/platform/database/migrations/046_shared_database_settings.sql:1), [049](/workspace/internal/platform/database/migrations/049_shared_database_tls.sql:1)). The store reads `id=1` and upserts it in [`shared_settings.go`](/workspace/internal/modules/dbconn/adapter/sqlite/shared_settings.go:19). A new migration must carry that row’s host, credentials, TLS mode, and sealed PEMs to the PostgreSQL kind without dropping user data. SQLite supports limited direct `ALTER TABLE` operations; changing the primary key/check constraint may require a table-copy migration, done transactionally while preserving the row. [SQLite `ALTER TABLE`](https://sqlite.org/lang_altertable.html).

The migration runner sorts embedded SQL files, checks SHA-256 checksums against `schema_migrations`, rejects edited or missing applied migration files, and applies each new migration in a transaction in [`migrate.go`](/workspace/internal/platform/database/migrate.go:35). Keep existing migrations unchanged. Fiber v3 accesses a route parameter with `c.Params("kind")`; the package docs also expose `fiber.Params[string](c, "kind")` ([Fiber v3 docs](https://pkg.go.dev/github.com/gofiber/fiber/v3)). Existing settings routes are `/api/settings/database`, admin-gated in [`bootstrap/dbconn.go`](/workspace/internal/bootstrap/dbconn.go:40); their response returns only `{configured}` to non-admins in [`shared_settings.go`](/workspace/internal/modules/dbconn/adapter/http/shared_settings.go:61).

The app can register at `POST /api/auth/register`; registration sets an HttpOnly `session` cookie ([`handler.go`](/workspace/internal/modules/account/adapter/http/handler.go:58), [`handler.go`](/workspace/internal/modules/account/adapter/http/handler.go:111); cookie name [`security.go`](/workspace/internal/platform/httpserver/security.go:10)). A project can be created with authenticated `POST /api/projects/` ([`handler.go`](/workspace/internal/modules/project/adapter/http/handler.go:25)).

**Needs DevOps:** a temporary logged-in app instance and a cookie-capable capture flow. Minimum flow: POST registration, save the `session` cookie, inject it into a browser context for that app origin, then capture `/app/projects` and the chosen project route at 1280×800 and 390×844. A Playwright script can do this once Playwright is available; otherwise extend/wrap the existing CDP capture flow to set a cookie before navigation. The existing capture tool cannot accept the cookie directly.

## Quality checks (QA/Reviewer/Security)

- **Isolation:** create project A and B users. MySQL A should succeed on A’s database and be denied on B’s; MongoDB A should have only `readWrite` on A’s database and fail authorization on B. Verify the Mongo user’s roles/authSource and that generated MySQL grants are limited to ``db``.*. If no local server is available, report that the runtime isolation check was not run.
- **Injection and credentials:** submit hostile project identifiers and assert the provisioner uses only generated identifiers; test invalid names at the domain boundary. Check errors/logs do not reveal MySQL DSNs, SQL containing generated passwords, Mongo URIs, passwords or PEMs. Cover MySQL’s `caching_sha2_password` against the supported TLS/no-TLS server setup.
- **PEM and access:** test valid/invalid CA, client cert/key pair mismatch, oversized material, explicit removals, and persistence sealing. Assert no PEM is returned by GET. Verify admin GET/PUT and non-admin GET returning only `configured`; non-admin writes are forbidden.
- **Detach and failure paths:** verify switching to SQLite removes only managed connection/environment entries and drops no database or user. Force provisioning failure and confirm old environment values are restored.
- **UI states/screenshots:** inspect configured and unconfigured database options, disabled option explanation, Settings link for admins, legacy read-only state, loading/error/saved/remove states, keyboard operation, focus visibility, labels and narrow-screen overflow. Capture Projects list plus Tasks, About, Env, Database, Checks and Files at desktop and mobile widths; check both no console errors and readable table/form layouts.

# Navigation simplification — technical research (2026-10-27)
**Repository:** farismnrr/agentic-ai-workspace, ref `dev`. **Scope:** read-only source audit and official UX/accessibility research. No implementation, builds, or runtime tests were performed.

## Requested behavior
- Hide **Tasks**, **Archive**, and **Extensions** from global sidebar.
- Existing **Projects → [project] → Tasks** is primary task access; preserve global `/app/tasks` URL for existing links.
- Expose Archive and Extensions under **Settings → Workspace** but preserve their original full-page routes, data operations, and direct/deep links.
- All roles must be able to reach Archive/Extensions (do not inherit admin-only restriction of Database).

## Verified source structure (branch dev)
- `web/src/features/workspace/shell/Sidebar.svelte` contains direct `NavItem` links to `/app/tasks`, `/app/archive`, `/app/extensions`. **Only remove those global entries.** Do not remove sidebar recent/pinned/project task entries.
- `web/src/features/workspace/shell/MobileBar.svelte` already has only Home, Inbox, Projects, Sites, Settings; no need to remove mobile bar entries.
- `web/src/features/workspace/settings/settings-nav.ts` has a Workspace section with only Database; `isAdminSettingsTab` restricts **only Database** and `visibleNavGroups` filters admin-only items.
- `web/src/features/workspace/settings/SettingsNav.svelte` currently constructs all hrefs from SettingsTab id: `/app/settings/{id}`. Direct links to Archive/Extensions require a separately typed destination, not inserting fake SettingsTab IDs.
- `web/src/features/workspace/settings/SettingsPage.svelte` renders SettingsTab components; avoid moving whole pages into this component.
- `web/src/app/router.ts` explicitly supports `/app/tasks`, `/app/archive`, `/app/extensions`, and `/app/extensions/:projectId`, plus `/app/projects/:projectId/tasks/:taskId`. Keep unchanged. `App.svelte` renders the independent components; do not redirect or duplicate routes.
- `web/src/features/workspace/projects/ProjectDetailPage.svelte` has a default Tasks tab; `projects/TasksTab.svelte` filters tasks by project and reuses TaskSelection. Global TasksPage is aggregated across projects, so removing the sidebar entry changes **discovery**, not the underlying route or model.
- `web/src/features/workspace/tasks/ArchivePage.svelte` includes archived task list, restore, and delete through `TaskSelection`; preserve mutations and API.
- `web/src/features/workspace/extensions/ExtensionsPage.svelte` accepts projectId and can show install instructions from task-driven deep links. Do not flatten/replace with Settings tab or lose dynamic route.
- `shell/commands.ts` currently lacks Archive/Extensions shortcuts; recommend adding these two search commands to preserve secondary discoverability (optional if minimizing scope is imperative).
- `shell/Topbar.svelte` receives crumbs from each page; provide Settings → Archive / Settings → Extensions breadcrumb back to Settings if these are entry points in Settings.
- Human docs `docs/using-the-app.md` and `docs/extensions.md` explicitly tell users to open Extensions from sidebar; update them.

## Design decisions
1. Primary sidebar remains: New task, Search, Inbox, All projects, Sites, plus recent/pinned/project lists and Settings.
2. Under Settings → Workspace, **Archive** and **Extensions** are ordinary navigational links targeting original routes. Database remains admin-only.
3. Preserve full Archive and Extensions pages, original paths and authorization. Do not create `/app/settings/archive` or `/app/settings/extensions` aliases unless a specific need arises.
4. Model destination explicitly in settings nav (`href` or discriminated union tab/route) to avoid unsafe casting to SettingsTab. Make active indication and return breadcrumbs coherent.
5. Check mobile horizontal SettingsNav scrolling and layout widths; no extra Settings page nesting or one-off styling.
6. Keep task selection, archiving/restoring, extension removal/install deep link working.

## External references
- NN/g Utility Navigation: low-frequency utility items can live in secondary navigation, but burying important actions makes them harder to find; keep legible labels and test discoverability: https://www.nngroup.com/articles/utility-navigation/
- W3C WAI Menu Structure: use labeled nav, clear current-page indication, and consistent destinations across viewport sizes: https://www.w3.org/WAI/tutorials/menus/structure/
- W3C WAI navigation landmarks: distinguish multiple nav regions with labels: https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/
- Repo's `AGENTS.md`, `agents/memory-frontend.md`, `agents/self-improvement.md`, `docs/design-system.md` guide styling, rules and verification.

## Risks and mitigations
- **Settings navigation typed to SettingsTab:** introducing fake tabs or in-app redirects can regress routes; support direct links as first-class nav item type.
- **Permissions:** Workspace currently includes admin-only Database; filter permissions per entry so Archive/Extensions show to ordinary signed-in users.
- **Extension install deep link:** retain `/app/extensions/:projectId`, installation highlighting and scroll behavior.
- **Lost orientation after opening full pages:** add a Settings breadcrumb/return path and consider Settings active state in global nav.
- **Discovery:** user-requested removal is appropriate, but secondary entry via Settings and optionally Command Palette must be tested.
- **Documentation drift:** fix references to sidebar destinations.
- **No runtime proof yet:** agent must run automated checks and browser journeys before claiming completion.

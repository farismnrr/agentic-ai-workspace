# PRD — Sidebar information architecture cleanup
## Goal
Remove redundant/low-frequency global sidebar entries (**Tasks**, **Archive**, **Extensions**) without removing functionality, changing APIs, or breaking existing links. Make active tasks accessible through the existing project Tasks tab. Provide discoverable links to Archive and Extensions under **Settings → Workspace**.

## Functional requirements
- R1 Remove exactly three global `Sidebar.svelte` top-level navigation entries: Tasks, Archive, Extensions. Do not remove SidebarPinned/Recent/Projects, inbox, search, sites, Settings or mobile dock entries.
- R2 `/app/tasks` remains a valid route for bookmarks, despite its global entry removal. Project Tasks tab works for every project, with normal task selection/actions and deep links to task threads.
- R3 Settings → Workspace includes Archive and Extensions for signed-in users with ordinary access. Existing Database link stays admin-only.
- R4 Archive link opens full `/app/archive` page and keeps list, restore, delete and confirmation behavior, including direct navigation and refresh.
- R5 Extensions link opens full `/app/extensions` page; existing `/app/extensions/:projectId` stays functional and highlights installer instructions.
- R6 Keep user orientation/return navigation: clear Settings → Archive / Settings → Extensions breadcrumb links, appropriate active nav state, no orphaned screens; optionally add Command Palette shortcuts for Archive and Extensions.
- R7 No change to backend APIs, persistence, roles, task lifecycle, extension installation mechanics, or global URLs.
- R8 Follow existing Svelte 5, TypeScript strict, daisyUI semantic theme, reusable components, 200-line rule and branch dev discipline.
- R9 Update outdated human docs under `docs/using-the-app.md` and `docs/extensions.md` on how to reach Extensions.

## Acceptance criteria
1. On desktop and drawer, none of the three names appears as **top-level sidebar entries**; tasks may still appear as recent/pinned/project entries.
2. Projects → any project → Tasks works; `/app/tasks` direct navigation still renders.
3. Settings → Workspace displays Archive + Extensions for nonadmin and admin; Database is hidden from nonadmin.
4. Clicking Settings Archive opens `/app/archive`, and task restore/delete still works.
5. Clicking Settings Extensions opens `/app/extensions`; deep linking to `/app/extensions/:projectId` still shows install instructions.
6. Browser refresh, back/forward, direct URL, Ctrl/Cmd+K search if enhanced, and breadcrumb back-to-settings work.
7. All navigation is accessible with mouse, keyboard and screen reader landmarks/active-state. No mobile horizontal overflow at widths 390/820/1024/1440 px.
8. Relevant unit/component tests and `make verify` pass. Fast CI green on dev, with deployment steps only according to repo rules.

## Out of scope
Do not replace page components with Settings-tab content, rename URL paths, add redirect aliases, change authorization logic, refactor API/backend, alter task storage, add dependencies, or alter unrelated UI.

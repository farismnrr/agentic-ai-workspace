# PRD: Reliable Context Window and Auto-Compaction

Problem: context meter can remain at 100% when CLI usage is cumulative or stale; API preflight is only partly verified. Prior fix commit 9ec545f.

Acceptance criteria:
1. API initial-full/resume triggers compact before normal model call, including huge tool outputs, preserving user instructions.
2. Failed compact has bounded retry and actionable failure, no identical oversized request loop.
3. Codex and Claude meter reflect actual last-call occupancy only, not cumulative tokens; unknown measurements are explicitly unknown, never stale 100%.
4. Live CLI events update meter when trustworthy usage is available, with no fabricated reset.
5. Native CLI context-full handles recovery through supported CLI mechanism or explicit actionable failure, never silently drops session.
6. E2E scenarios reproduce initial-full, compact success/failure, resume, and browser meter; tests and code review pass.

Scope: application/compact.go, overflow.go, CLI stream parsers, CLI events, planmeter, UI and black-box tests. Avoid unnecessary whitebox tests or unrelated refactoring. Traceability: PRD -> research -> plan -> code -> E2E evidence -> review -> commit.
